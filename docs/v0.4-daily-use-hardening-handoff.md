## 5. 恢复入口

继续时先确认：

```powershell
$safeRepo = (Resolve-Path .).Path -replace '\\', '/'
git -c "safe.directory=$safeRepo" status -sb
git -c "safe.directory=$safeRepo" log --oneline -5
```

然后从最终分支 HEAD 运行 Windows amd64 release smoke，再 push、创建 PR 并跟踪
GitHub Actions。所有二进制、数据库、日志、录制和临时证据仍写入仓库忽略的
`.tmp/`，不得写入公开 evidence 目录。

## 6. 本地缓存与临时目录审计

2026-08-15 先完成只读盘点；2026-08-16 已按确认的保留清单实施项目级缓存环境和
历史 `.tmp` 清理。

### Go

- Go 可执行文件位于 E 盘，但安装位置不决定缓存位置。
- 未显式设置环境变量时，`GOPATH`、`GOCACHE` 和 `GOMODCACHE` 仍指向
  `<user-profile>` 下的默认目录。
- `GOTMPDIR` 为空，因此 Go 构建的短生命周期工作目录仍使用系统 `%TEMP%`。
- 原始 Phase 5 构建把 `GOCACHE` 和 `GOMODCACHE` 指向仓库 `.tmp/go/`，但没有设置
  `GOTMPDIR`，所以构建期间仍可能短暂写入系统临时目录；成功后没有留下
  `go-build*` 残留。
- `scripts/build-local.ps1`、`scripts/build-release.ps1` 和
  `scripts/verify-local.ps1` 在本次续作前只解析 Go 可执行文件，没有统一设置本地 Go
  cache/temp 环境。

### 其他缓存

- 本机 npm 包装器会强制覆盖 `NPM_CONFIG_CACHE`。项目脚本现显式传入 `--cache`，
  确保实际缓存使用仓库 `.tmp/cache/npm/`，不修改全局 npm 配置。
- website Playwright 浏览器位于仓库忽略的 `website/.playwright-browsers/`。
- frontend Playwright 在 Windows 优先使用非系统盘共享目录，失败后才回落到仓库目录。
- 用户级 pip cache 和历史 Playwright 浏览器仍在用户目录；它们是工具级共享缓存，
  不是 v0.4 Phase 5 的必要证据。

### 已落地的长期布局

为了不写系统盘，同时避免 Hook 把测试临时仓库误识别为当前项目，缓存分为两层：

```text
<repo>/.tmp/cache/go-build       GOCACHE
<repo>/.tmp/cache/go-mod         GOMODCACHE
<repo>/.tmp/cache/gopath         GOPATH
<repo>/.tmp/cache/npm            可选 npm_config_cache
<repo>/.tmp/cache/pip            可选 PIP_CACHE_DIR
<workspace-parent>/.tmp/AgentToolGate-public-go       GOTMPDIR
<workspace-parent>/.tmp/AgentToolGate-public-runtime  TEMP / TMP
<workspace-parent>/.tmp/AgentToolGate-public-pycache  PYTHONPYCACHEPREFIX
```

`scripts/local-cache-env.ps1` 只修改当前 PowerShell 进程，不写用户级或机器级环境变量。
`build-local.ps1`、`build-release.ps1` 和 `verify-local.ps1` 已统一复用。`GOTMPDIR`、
`TEMP` 和 `TMP` 位于仓库外的同盘工作区临时目录，避免进入 Hook 保护范围。
