## 1. 候选范围

`v0.3.1-rc1` 在 `v0.3.0` 的治理与评估基线上，重点完善 Codex 项目级 Hook 接入：

- `init codex` / `init all` 生成项目 `.codex/config.toml` 和自包含 Hook bundle。
- `init codex --refresh-hooks` 只刷新 adapter/Core，并把被替换文件保留到项目本地
  recovery 目录。
- `up` 在成功监听后发布真实 loopback endpoint 和当前可执行文件路径。
- `doctor --dir` 分开报告安装状态、Git/Python 依赖、运行模式与两层信任要求。
- ATG 运行目录通过 Git 本地 `info/exclude` 隐藏，Hook 不生成 `__pycache__`，避免污染
  目标仓库。

这些能力仍是客户端 Hook guardrail 和工具治理网关，不是 OS sandbox、EDR 或完整 DLP。
Codex 项目信任与 Hook 内容信任仍需用户在客户端中显式确认。

## 4. Windows 主包验收

在一次性 Git 仓库中运行从 Release 解压的 `agenttoolgate.exe`，没有修改用户全局
Codex / Claude 配置。

- `doctor --dir` 显示版本 `v0.3.1-rc1` 和正确提交。
- `init codex` 成功生成项目 TOML、adapter、Core、项目配置和客户端片段。
- `doctor --dir` 在初始化后显示：
  - Codex 项目配置：`configured`
  - Codex Hook adapter：`current`
  - Codex Hook core：`current`
- `up` 使用非默认端口 `51351` 启动。
- `GET /health` 返回 HTTP 200。
- `GET /` 返回 HTTP 200 和嵌入式前端 HTML。
- control 中的 endpoint 为本次实际 loopback 地址，不会回落到默认 `8080`。

### 4.2 Hook 行为与后置条件

本轮直接运行 `init codex` 安装的产品 Hook，验证 adapter/Core 与运行中后端的真实链路；
没有把它表述为真实 Codex CLI 会话验收。

- 普通 `git status` payload：进程退出码 0，stdout 为 0 字节。
- synthetic `apply_patch` 写 `.ssh/authorized_keys`：
  - `permissionDecision=deny`
  - reason：`命中敏感写入`
- 独立文件系统检查确认目标文件不存在。
- `.tmp/agenttoolgate/` 由项目 Git 的 `info/exclude` 命中，没有出现在
  `git status --porcelain`。
- 项目中没有生成 `__pycache__`。
- 验收结束后 control 已恢复 `off`，endpoint 和 executable 字段均已移除。
- AgentToolGate 进程已停止，端口 `51351` 不再监听。
