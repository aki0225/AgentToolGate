## 1. 验收范围

本轮验证 `v0.4` 日常使用加固，不把它描述成 OS sandbox、完整 DLP 或企业级生产
控制。范围包括：

- Hook 生命周期、`off` / `dry-run` / `live` 和服务退出行为。
- 普通开发低干扰与高危本地动作阻断。
- Secret、HTTP SSRF、MCP inbound/outbound 和审批边界。
- 项目规则校验、解释和跨平台发布脚本。
- 前端控制台、展示站与 Windows amd64 发布包。

所有临时二进制、日志、数据库和浏览器结果都写入忽略的 `<repo>/.tmp/` 或同盘
workspace 临时目录。未执行原始危险命令；删除、敏感读取和网络外传只作为 Hook JSON
输入探针。

## 3. Hook 真实验收

在 `<repo>/.tmp/` 下创建独立嵌套 Git 项目，通过当前源码构建的二进制执行 `init all`
与动态端口 `up`：

- `dry-run` 精确产生 4 条脱敏预览，不阻断。
- `live` 下普通 `git status`：Codex 零输出放行，Claude 返回协议允许结果。
- Codex 与 Claude 均拒绝敏感读取、根递归删除、网络外传和受保护路径写入。
- 本地 collector 请求数为 0；sentinel、HEAD、tree 和目标文件 Hash 均不变。
- 服务异常停止后，高风险输入 fail closed；两个明确低风险动作进入 pending audit。

100 个 warm 样本下，Codex 与 Claude 的 live p95 均低于 250ms；普通开发样本无失败或
超时。

## 4. Secret、HTTP 与 MCP

聚焦测试和源码复核确认：

- resolved Secret 在前后字符拼接、嵌套 JSON 和重叠值中仍会精确脱敏。
- HTTP / MCP 出站按请求和 redirect 重新解析 DNS，拒绝 metadata、link-local 和
  非显式 loopback，并固定拨号到本次校验 IP。
- HTTP / MCP 出站禁用环境代理。
- MCP outbound 限制 SSE 单行 64 KiB；SSE event、POST request/response 和 JSON-RPC
  result 各 1 MiB；最多 256 tools，单个 input schema 64 KiB。
- MCP inbound 请求和响应限制为 1 MiB，拒绝尾随 JSON。
- MCP outbound 响应必须匹配 JSON-RPC 版本与请求 ID，且 result/error 二选一。
- 工具参数错误使用显式类型映射，不按错误字符串关键词决定是否公开。

边界仍然存在：显式 allowlist authority 可以解析到普通 RFC1918、IPv6 ULA 或 CGNAT
私网地址。当前实现不是完整私网隔离；若部署同时访问公网和内部服务，应在外部网络策略
或后续目标分区配置中继续限制。
