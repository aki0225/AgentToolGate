## 0. 冻结状态

`v0.3.0` 自 2026-08-11 起冻结，并在当时作为稳定版本：

- 不移动、覆盖或重新创建 `v0.3.0` 与 `v0.3.0-rc3` 标签。
- 不修改已经发布的附件、校验和或历史评估快照。
- `main` 后续只允许文档、展示站和必要维护；任何产品能力或安全语义变化从新版本开始。
- 如果发现安全缺陷，保留失败证据并在新提交、新评估 run 和新版本中修复，不回写历史
  通过结果。

## 1. 发布范围

`v0.3.0` 在 `v0.2.0` 基础上增加并验证了以下能力：

- 项目级受保护路径与网络写入规则。
- 项目规则只能提升为审批或拒绝，不能放松 Guard Core。
- 多目标 patch、复合命令、跨平台路径边界和可信项目根校验。
- 独立 reviewer、防自批、票据指纹、有效期、单次消费和 remembered allow。
- Claude、Codex、Go CLI 与 Python fallback 的一致安全下限。
- 评估附件可以脱离源码仓库复跑 quick suite 和治理不变量。

这些能力仍属于客户端 Hook guardrail 和工具治理网关，不是 OS sandbox、EDR、完整
DLP 或数据血缘系统。

## 3. 候选版本发现的问题

### v0.3.0-rc1

Release workflow `31466679004` 在 Windows 和 Linux 均失败。原因是发布脚本仍把
quick suite 数量硬编码为 18，而当前 suite 已扩展为 20 个用例。

修复提交：`197b8e9 修复：按评估套件动态校验发布摘要`

修复后发布脚本从实际 JSONL 非空用例数计算预期值，避免套件扩展后再次漂移。

### v0.3.0-rc2

Release workflow `31467388264` 成功，但从 Release 下载评估附件后，在脱离源码仓库
的目录中运行 governance suite 会保守失败：附件没有包含 evaluator 定位产品 Hook
所需的 `.codex/hooks/` 与 `.claude/hooks/`。

修复提交：`7a375e0 发布：让评估附件可独立复跑治理用例`

修复后：

- 评估附件包含运行治理不变量所需的四个产品 Hook 文件。
- Release smoke 不再只执行 `validate`，还会从解压后的附件实际运行 20-case quick
  suite。
- Windows 和 Linux Release job 均验证附件可以在没有源码仓库辅助的情况下运行。

### v0.3.0-rc3

Release workflow `31468721946` 的 Windows、Linux 和 Release job 全部成功。

从 GitHub Release 重新下载全部附件并完成：

- 五个附件存在且 `SHA256SUMS` 全部匹配。
- Windows / Linux `doctor` 显示 `v0.3.0-rc3` 和正确提交。
- Windows / Linux `init all` 成功生成项目配置、保护规则和客户端片段。
- Windows / Linux `up`、`/health`、`/`、MCP initialize、tools/list 和
  `mock.echo` 调用通过。
- Windows 评估附件：30 passed / 0 failed / 0 skipped。
- Linux 评估附件：26 passed / 0 failed / 4 skipped。
- Linux 的 4 个 skipped 均为明确的平台不适用用例。
- 验收后进程和监听端口均已停止。
