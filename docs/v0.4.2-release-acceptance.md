## 1. 发布范围

`v0.4.2` 是基于 `v0.4.1` 的 Hook 输入兼容补丁，不新增 Guard 规则，也不改变
`allow`、`ask`、`deny`、审批或审计语义。主要变化是：

- Codex、Claude 和发布包内嵌 Hook 在调用 `Path.resolve()` 前显式拒绝包含 NUL 的
  工作目录，不再依赖 Python 小版本或操作系统的隐式异常行为。
- `live` 异常输入继续 fail-closed；`off` / `dry-run` 不产生错误预览或 pending audit。
- CI 增加 Ubuntu / Python 3.10、Ubuntu / Python 3.14 和 Windows / Python 3.14
  兼容矩阵。
- Windows 8.3 短路径测试改为比较规范化项目根目录，不改变 Hook 返回规范路径的既有
  行为。

完整差异见
[`v0.4.1...v0.4.2`](https://github.com/aki0225/AgentToolGate/compare/v0.4.1...v0.4.2)，
实现与取舍见
[`v0.4.2 Python 3.14 Hook 兼容修复计划`](v0.4.2-python314-hook-compatibility-plan.md)。

验收使用公开 Release 下载地址重新下载五个附件，没有用本地 `dist/` 产物替代：

- 四个归档的本地 SHA256 与 `SHA256SUMS`、GitHub Release digest 完全一致。
- Windows 主程序 `doctor` 返回版本 `v0.4.2` 和正确提交；独立启动后 `/health` 与
  `/` 均为 HTTP 200，随后进程停止，验收端口 `18092` 不再监听。
- Windows 与 Linux 评估包中的产品二进制分别与同平台主程序包内二进制一致。
- Windows 正式评估包在 Python 3.14.3 下独立复跑 quick suite：20 passed、
  0 failed、0 skipped；6 个危险动作和 6 个治理不变量全部通过。
- 该 quick 复跑中审批前上游调用、自批成功、冻结参数篡改成功、Ticket 重放成功、
  Secret 泄漏和离线高风险放行均为 0；disposable sandbox 无残留。
- Windows / Linux 评估包内的 Codex 与 Claude Hook 均在 Python 3.14.3 下直接验证：
  `find_repo_root("bad\u0000cwd")` 明确失败，
  `find_repo_root_safely("bad\u0000cwd")` 返回 `None`。

Windows runner checkout 会把 Python Hook 写成 CRLF，Linux 和仓库源码使用 LF；统一
换行后，四个 Hook 文件的内容 SHA256 分别一致。该差异不改变 Python 逻辑，正式包中
的异常输入验证也已直接通过。

## 5. 证据边界

`v0.4.2` 的 Release workflow 已在原生双平台执行 quick suite，本次还从公开附件独立
复跑了 Windows quick。当前最新的**完整 30-case、双平台、版本化公开 Proof Pack**
仍绑定 `v0.4.1`；本次没有把该历史证据改名或冒充为 `v0.4.2` 结果。

因此可以确认本补丁的产品 CI、双平台打包、正式附件和 Python 3.14 异常路径，但不能
据此宣称已经为 `v0.4.2` 新生成完整 30-case 双平台 Proof Pack。若需要更新该层证据，
应先把正式附件复跑 workflow 从固定版本改为可校验的通用 Release 输入，再单独运行并
发布版本化结果。

## 6. 发布判断

`v0.4.2` 已达到兼容性补丁的正式发布条件，并成为当前稳定版。`v0.4.1` 的完整评估
证据继续作为上一版冻结快照保留，不回写其 run、附件、Hash 或当时结论。

本结论不改变项目边界：ATG 仍是工具调用治理网关和客户端 Hook guardrail；Hook 未
加载、未信任、被绕过、处于 `off` / `dry-run` 或未覆盖工具路径时，没有 ATG 实时
阻断。
